# Graduation Path — Open → Closed

Evolve a dynamic agent into a reliable workflow.

```
open ─→ refine ─→ lock in ─→ run dynamically ─→ run repeatedly ─→ CLOSED
explore        define the shape          prove it          operationalise
```

## When to graduate an open specialist into a closed one
- you have run the same shape of work 8+ times
- the inputs are predictable
- the output is verifiable (a file, a report, a scheduled action)
- the workflow does not need back-and-forth mid-run
- you can catch yourself typing the same opening prompt every time

## Example: an SEO agent (closed specialist)
`backlog (task queue) → inputs (keyword, brief) → SEO agent (runs on cron) → review step → publish`

Once the steps are stable, lock the tools, fix the IO, pick a cheap/fast model, and put it on the
backlog. It becomes a repeatable operator instead of a conversation.
