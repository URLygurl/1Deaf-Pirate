# Open vs Closed Specialists

Two types of agents. Same system. Same purpose. Both live in the Hermes system (sessions/memory,
tools/connectors, skills/frameworks, identity/config, backlog/cron, logs/observability).

## Open specialists — *you chat, you steer*
- Dynamic, flexible. Context grows across a long session.
- **Best for:** exploration, brainstorming, judgment calls.
- **You get:** faster iteration, more back-and-forth, dynamic direction.
- **Cost:** less structure, can drift off-topic, context gets heavy.
- **Output shape:** notes, drafts, ideas, brainstorms, judgment calls.

## Closed specialists — *they run, you get results*
- Repeatable, operational. Runs from a backlog or on cron.
- Scoped tools, defined inputs/outputs, cheap + fast model where it fits.
- **Best for:** repeatable production work.
- **You get:** consistent results, predictable output, verifiable artifacts.
- **Cost:** less interactive, needs upfront scoping, rigid if poorly designed.
- **Output shape:** report.md, article, file, analytics, published artifact.

## How Hermes routes
Hermes is useful when work touches multiple specialists, ownership is unclear, or you want one
synthesis. You can also talk to an open specialist directly — but the orchestrator is the default.

## When to keep an agent open
- the work is exploratory / creative
- inputs are unpredictable
- the right answer depends on your taste
- the use case is still being shaped — it's a brainstorm, analysis still in motion
