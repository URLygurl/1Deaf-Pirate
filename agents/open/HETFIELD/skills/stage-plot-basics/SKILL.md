# Stage Plot Basics

A stage plot and input list are the two documents that let a venue's audio crew set up a band quickly and correctly. The stage plot is a simple overhead map showing who stands where with what gear; the input list translates that picture into a numbered table of console channels. This skill explains the concepts and reviews a band's draft so a self-managing artist can hand a venue something a sound engineer actually trusts.

## Instructions
1. When explaining, define both documents plainly: the stage plot is "a top-down picture of the stage"; the input list is "the channel-by-channel recipe for the mixing console."
2. Explain why they matter: they enable line-checks before doors, correct monitor mixes, and a fast changeover; vague or missing plots cause delays and bad sound.
3. Cover the core stage-plot elements: performer positions, instruments, amps, drum riser, monitor wedges/IEMs, DI and power locations, and stage-left/right orientation from the performer's view.
4. Cover the core input-list columns: channel number, source, mic or DI, stand type, phantom power, and notes; plus the total channel count and number of monitor mixes.
5. When reviewing a draft, check for the common mistakes: mirrored stage-left/right, ambiguous mic/DI choices, missing phantom flags, no who-supplies-what marking, no channel total, and no monitor-mix count.
6. Give clear, prioritized fixes rather than a full rewrite when the user only wants a sanity check.
7. Point the user to produce the finished artifact with the stage-plot-input-list skill once concepts are clear.

## Examples
- "What's the difference between a stage plot and an input list?" → Explain the picture-vs-table distinction in plain language with a tiny example of each.
- "Here's my stage plot, does it look right?" → Review against the common-mistakes checklist and return prioritized, specific corrections.
- "Why does the sound guy keep asking for this?" → Explain how the documents drive line-check, monitor mixes, and changeover speed, and what goes wrong without them.

## Guidelines
- Keep explanations jargon-light for self-managing artists, but use the real engineer terms (DI, phantom/48V, wedge, IEM, FOH) and define them inline.
- Always emphasize stage-left/right is from the performer's perspective — the single most common confusion.
- For reviews, lead with the highest-impact issue and don't bury fixes in prose.
