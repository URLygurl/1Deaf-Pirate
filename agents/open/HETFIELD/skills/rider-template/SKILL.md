# Rider Template

A technical rider is the complete document a band sends ahead of a show so the venue, promoter, and production crew know exactly what the act needs to perform. It bundles the contact/advance block, the stage plot, the input/channel list, backline requirements, PA and monitor needs, power and stage requirements, and often hospitality and logistics. This skill assembles those parts into one coherent, professional template the user can fill in and reuse per tour.

## Instructions
1. Start with a header/advance block: band name, document version and date, tour-manager/production contact (name, phone, email), and show advance deadline.
2. Add a short performance overview: lineup size, set length, number of acts/changeover time, and anything unusual (playback, click track, special effects).
3. Insert the stage plot section: reference or embed the top-down plot; if not yet built, point to the stage-plot-input-list skill to create it.
4. Insert the input/channel list: the numbered table plus channel total and monitor-mix count.
5. Add the backline section: supplied amps/drums/keys with alternates and a BAND vs. PROVIDED column; defer detail to the backline-rider skill if it needs building.
6. Add PA and monitors: required system coverage/SPL expectations, number and type of monitor mixes (wedges/IEMs), and FOH/monitor console minimums.
7. Add power, stage, and logistics: power drops, stage size minimum, load-in access, parking, and crew needed.
8. Add hospitality/logistics if requested: green room, catering, towels, water, and guest list lines.
9. Close with a confirmation/sign-off line and restate that substitutions and changes require tour-manager approval in advance.

## Examples
- "Put together a full tech rider for our band." → Produce the complete sectioned template (header, overview, stage plot, input list, backline, PA/monitors, power/stage, hospitality, sign-off) with placeholders where details are missing.
- "What sections should a rider have?" → List the standard sections in order and explain what each communicates to the venue.
- "Merge our stage plot and backline list into one rider." → Combine existing artifacts under the standard headers, add a contact block and sign-off, and flag any missing sections.

## Guidelines
- Build a reusable template with clear placeholders; do not invent specifics the user hasn't given — mark them TBD and ask.
- Keep sections in the conventional order so production managers can scan quickly.
- Cross-reference rather than duplicate: pull the channel map from stage-plot-input-list and gear specs from backline-rider instead of re-deriving them.
- Always include a contact block and an advance/approval line — riders without a reachable contact get ignored.
- Output should be a clean, sectioned document ready to export to PDF and email. Canonical reference: https://www.musicnsw.com/resources/tech-rider-stage-plot-template
