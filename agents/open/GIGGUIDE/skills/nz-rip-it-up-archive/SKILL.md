# Rip It Up Archive (Papers Past)

Rip It Up was the long-running New Zealand music newspaper founded by Murray Cammick in 1977, running until 2015. Its digitised back catalogue is hosted on Papers Past (National Library of NZ), making it the primary source-of-truth for NZ scene history, period gig listings, reviews, charts and band interviews. The RIU Calendar / Gig Guide ran from 1981 and is a goldmine for reconstructing who played where and when.

## Instructions
1. Treat Papers Past as the canonical archive: https://paperspast.natlib.govt.nz/periodicals/rip-it-up
2. When the user wants a specific issue, narrow by date or year first; Rip It Up was monthly, so map the request to a month/year.
3. For gig-history questions, look to the Calendar / Gig Guide section (present from 1981 onward) rather than editorial pages.
4. Quote sparingly and attribute: cite issue date and page where possible. Flag transcription/OCR uncertainty.
5. If a fact cannot be confirmed from the archive, keep the answer general and say so rather than inventing issue numbers, dates, or quotes.
6. Cross-reference with AudioCulture or the RIU history skill when context (people, labels, scenes) is needed.

## Examples
- "Find the Rip It Up review of the first Flying Nun releases." -> Point to early-1980s issues on Papers Past, explain how to locate by date, note OCR caveats, attribute to RIU.
- "What gigs were listed in Rip It Up around mid-1984?" -> Direct to the RIU Calendar/Gig Guide for that period; reconstruct cautiously, flag gaps.
- "Who founded Rip It Up and how long did it run?" -> Murray Cammick, 1977-2015; offer the Papers Past archive link for deeper reading.
- "Cite a Rip It Up interview with a NZ band from the 90s." -> Locate by year on Papers Past, attribute issue/date, avoid fabricating quotes.

## Guidelines
- DO attribute every claim to an issue date/page when possible; DO note OCR can garble names and dates.
- DO keep Papers Past as the single canonical URL for this skill.
- DON'T invent issue numbers, cover dates, or quotes; if unsure, stay general.
- DON'T use this for upcoming/live listings — route those to the gig-guide skills.
- EDGE CASE: some years may have gaps in digitisation; acknowledge missing coverage rather than guessing.
- OUTPUT: a sourced pointer (year/month/section) plus a short, attributed summary.
